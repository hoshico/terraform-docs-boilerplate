# AWS 構成図の作成規約

このディレクトリの draw.io 図は、AWS 構成を正確かつレビュー可能な形で表現するための成果物である。
本書は既存の図の見た目を前提にしない。図を新規作成・大規模更新する際は、
`.github/skills/aws-drawio/SKILL.md` を読み、この規約と併用すること。

## 1. 正確性を優先する順序

矛盾がある場合は、次の順で判断する。

1. ユーザーが明示した要件とレビュー時の合意
2. `requirements/communication.yaml` のリソースと通信要件
3. 本ファイル
4. プロジェクト Skill と公式 draw.io Skill / MCP の一般ルール

YAML にないリソース、通信、ポート、可用性構成を推測で図に追加しない。
不足情報は注記で明示するか、確認を求める。

## 2. AWS アイコンと境界

- AWS サービスは draw.io の AWS4 ライブラリ（`mxgraph.aws4.*`）を使う。
- アイコン名を推測しない。公式 draw.io MCP の `search_shapes`、または検証済みの
  アイコンカタログで確認してから使う。
- AWS Cloud、Account、Region、VPC、Availability Zone、Subnet は、要件に存在する
  境界だけをコンテナで表現する。
- コンテナは入れ子関係が分かる配置とし、内部リソースをコンテナの子要素にする。
- サービスアイコンはリソース種別と名称の両方が分かるようラベルを付ける。

## 3. レイアウトと通信

- 主なリクエスト／データフローは左から右へ置く。分岐は縦方向のレーンで表す。
- 通信線は始点・終点を必ず実在する図形へ接続し、矢印で方向を示す。
- 通信要件に protocol と port がある場合、線ラベルに `TCP 443` の形式で必ず表示する。
- 線、線ラベル、アイコン、コンテナ見出しを重ねない。交差が必要なら、ノード位置または
  直交経路を調整する。
- 非同期、管理通信、レプリケーションなど主経路と性質が異なる線は、破線など明確に
  区別した表現を使い、凡例を置く。

## 4. 生成・更新手順

1. 要件からリソース、境界、通信をリスト化する。
2. AWS4 アイコンを検証してから、コンテナ、リソース、通信線の順に配置する。
3. `.drawio` は非圧縮 XML で保存し、draw.io で開き直せることを確認する。
4. draw.io Desktop CLI で SVG をエクスポートする。SVG は直接編集しない。
5. SVG または PNG を目視確認し、空のアイコン、重なり、切れたラベル、誤った矢印方向を
   修正する。
6. YAML の全リソース・全通信と図を突き合わせる。

## 5. 完了条件

- YAML にある全リソースが図にある。
- YAML にある全通信について、送信元、宛先、方向、protocol、port が一致する。
- 図を開き直せ、SVG が最新の `.drawio` から出力されている。
- AWS アイコンが空白や汎用図形に置き換わっていない。
- アイコン、通信線、ラベルが読みやすく、不要な交差や重なりがない。
